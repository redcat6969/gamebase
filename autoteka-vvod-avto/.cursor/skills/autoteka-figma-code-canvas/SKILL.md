# Автотека: код и канвас Figma

Проект: статическая вёрстка `index.html` + `styles.css` (макс. ширина 375px, экран «Ввод авто»). В CSS указана сверка с макетом Figma (`node 147:27757`). Шрифт: Manrope (Google Fonts). Копия интерфейса на русском.

## Обязательные скиллы Figma

Перед **`use_figma`** всегда загружай скилл **figma-use** из набора Cursor / Figma (Plugin API: цвета 0–1, шрифты, инкрементальные шаги, страницы).

Для **сборки или крупного обновления экрана в Figma из кода** дополнительно загружай **figma-generate-design**: сначала `search_design_system` / инстансы в файле, потом `use_figma` с компонентами библиотеки, не голыми прямоугольниками.

При вызове `use_figma` в рамках этого скилла передавай `skillNames: "autoteka-figma-code-canvas,figma-use"` (и при необходимости добавь `figma-generate-design`).

## Когда что использовать

| Задача | Инструмент |
|--------|------------|
| Первый раз отправить текущую страницу в Figma «как в браузере» | `generate_figma_design` |
| Править существующий фрейм, переменные, компоненты после захвата | `use_figma` (+ при полном экране — workflow из figma-generate-design) |
| Понять макет или снять скрин для сверки | `get_design_context` / `get_screenshot` / `get_metadata` |
| Найти компоненты библиотеки перед созданием нового | `search_design_system` |

Подход из [блога Figma](https://www.figma.com/blog/the-figma-canvas-is-now-open-to-agents/): **`generate_figma_design`** и **`use_figma`** дополняют друг друга — захват даёт пиксельную копию, ручная сборка через дизайн-систему даёт связанные инстансы. Для веб-страницы можно комбинировать (см. figma-generate-design: параллельно захват и сборка, потом сверка и удаление временного захвата при необходимости).

## Инструкция агенту

1. **Локальный превью URL.** Подними статику в каталоге проекта и получи URL (например `http://127.0.0.1:8080` или порт из вывода сервера). Убедись, что открывается `index.html`.
2. **Захват в Figma.** Вызови `generate_figma_design` без `outputMode`, затем по ответу MCP выбери режим:
   - **newFile** — задай осмысленный `fileName` (например `Autoteka — Ввод авто`) и `planKey` из списка планов, который вернул MCP (team/org).
   - **existingFile** — у пользователя есть `fileKey` (из URL или недавних файлов); при необходимости `nodeId` для вставки.
3. **Поллинг.** Если инструмент вернул `captureId`, опрашивай каждые ~5 с (до ~10 раз), пока статус не `completed`.
4. **Правки на канвасе.** Для изменений структуры/токенов/компонентов — после шага 1 из figma-use напиши короткий `use_figma`-скрипт; возвращай ID затронутых нод.
5. **Сверка с кодом.** Токены страницы заданы в `:root` в `styles.css` (`--bg-page`, `--bg-hero`, `--text-primary`, радиусы, тень и т.д.) — при обновлении переменных в Figma опирайся на них.

## Токены и размеры (кратко)

- Фон страницы: `#ffffff`, hero-слой: `#f2f1f0`, текст основной `#000000`, вторичный `#757575`.
- Скругления карточки/экрана: верх ~28px, нижний левый 30px (см. `--radius-*` в CSS).
- Высота серого hero-фона: 340px (`--hero-bg-height`).

## Частые сбои

- Файл только что создан через claim — пользователь должен открыть claim-ссылку в браузере до `existingFile`.
- Неверная страница в многостраничном файле — в начале скрипта `await figma.setCurrentPageAsync(...)` (см. figma-use).
- Нет шрифта — перед текстом `await figma.loadFontAsync({ family: 'Manrope', style: '...' })` (стили из макета).

## Пример запроса пользователя

**Ввод:** «Залей текущую страницу в новый файл Figma в команде X».

**Ожидаемое действие:** Старт сервера → `generate_figma_design` с `outputMode: newFile`, `fileName`, `planKey` → поллинг → сообщить `fileKey` и ссылку на файл.
